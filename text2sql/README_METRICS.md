# Comprehensive Metrics Guide

## Overview

This project now includes comprehensive metrics for comparing GPT and Ollama models on Text-to-SQL tasks.

## Available Metrics

### 1. **Execution Accuracy (EX)** ✅ Already Implemented
- **Measures**: Functional correctness
- **How**: Runs generated SQL vs. gold SQL on database, compares result sets
- **Why**: Gold-standard metric - ensures query retrieves the right answer

### 2. **Exact Match (EM)** ✅ Already Implemented
- **Measures**: Syntactic correctness
- **How**: String match between generated SQL and reference SQL (case-insensitive, normalized)
- **Why**: Ensures same SQL form (though not all equivalent queries match exactly)

### 3. **Semantic Match (SM)** ✅ NEW
- **Measures**: Logical equivalence
- **How**: Checks whether both queries have same logical operations (SELECT, WHERE, GROUP BY, etc.) even if SQL syntax differs
- **Why**: Captures alternative valid formulations that EM misses
- **Implementation**: Uses sqlglot to parse and compare query structure

### 4. **F1-Score** ✅ NEW
- **Measures**: Token-level SQL overlap
- **How**: Computes precision/recall of SQL tokens vs. gold SQL
- **Why**: Useful to capture partial correctness (e.g., correct columns but wrong filter)
- **Formula**: F1 = 2 * (Precision * Recall) / (Precision + Recall)

### 5. **BLEU Score** ✅ NEW
- **Measures**: Text similarity (n-gram overlap)
- **How**: Compares n-gram overlap between predicted and gold SQL
- **Why**: Measures fluency/structure similarity; standard in NLP-to-SQL papers
- **Formula**: BLEU = brevity_penalty * geometric_mean(precision_1, precision_2, ..., precision_n)

### 6. **ROUGE-L Score** ✅ NEW
- **Measures**: Longest Common Subsequence (LCS) similarity
- **How**: Finds LCS between gold and generated SQL tokens
- **Why**: Captures sequence-level similarity, complementary to BLEU
- **Formula**: ROUGE-L = F1 of LCS precision and recall

### 7. **Latency / Inference Time** ✅ Enhanced
- **Measures**: Efficiency
- **How**: Tracks generation latency + execution latency separately
- **Why**: Useful when comparing Ollama (local) vs GPT (API)
- **Reported**: Total latency, generation latency, execution latency

### 8. **Token Usage / Cost** ✅ NEW
- **Measures**: Economic efficiency
- **How**: Tracks input + output tokens, calculates cost based on model pricing
- **Why**: Essential when comparing GPT (paid) vs Ollama (free local)
- **Calculation**: 
  - GPT: Uses OpenAI pricing ($0.15/$0.60 per 1M tokens for gpt-4o-mini)
  - Ollama: Free (0.0)

### 9. **Memory Footprint** ✅ NEW
- **Measures**: Hardware usage
- **How**: Tracks CPU and GPU memory utilization during inference
- **Why**: Shows scalability for local deployment
- **Note**: Requires `psutil` and `torch` (optional)

### 10. **Robustness / Error Rate** ✅ NEW (via success rate)
- **Measures**: Stability
- **How**: Tracks success rate across multiple test cases
- **Why**: Checks generalization ability
- **Reported**: Success rate in batch evaluation

## Usage

### Single Query Evaluation (app.py)

1. Enable "Evaluation Mode" in sidebar
2. Enter your question
3. Paste "Gold SQL"
4. Click "Generate SQL"
5. View all metrics:
   - EM, EX, SM (checkmarks)
   - F1-Score, BLEU, ROUGE-L (numeric)
   - Tokens, Cost, Latency (performance)
   - Detailed breakdown in expander

### Model Comparison (comparison_app.py)

Run side-by-side comparison:
```bash
streamlit run comparison_app.py
```

Features:
- Compare GPT vs Ollama on same query
- Batch evaluation across multiple test cases
- Aggregated metrics across all tests
- Export results as JSON

## Gold SQL Explained

### What is Gold SQL?

**Gold SQL** is the **correct/reference SQL query** that answers your question accurately.

### Where Does It Come From?

1. **Manual**: You write it yourself (you know it's correct)
2. **Benchmark Dataset**: From evaluation datasets like Spider
3. **Expert Verified**: Generated by SQL expert and verified
4. **Reference Implementation**: The "official" way to answer the question

### Example:

```
Question: "Average hours_per_week by education (top 10)"

Gold SQL:
SELECT education, AVG(hours_per_week) AS avg_hours
FROM adult_income
GROUP BY education
ORDER BY avg_hours DESC
LIMIT 10
```

### How It's Used:

1. **Exact Match (EM)**: Compares if generated SQL string matches gold SQL exactly
2. **Execution Accuracy (EX)**: Executes both queries, compares results
3. **Semantic Match (SM)**: Checks if logical structure matches
4. **F1/BLEU/ROUGE**: Measures similarity at token/sequence level

### Without Gold SQL:

- You can still use the app (generates SQL)
- But **cannot calculate accuracy metrics**
- Only see if SQL executes successfully
- No way to know if it's the "right" answer

### Getting Gold SQL:

1. **Test Your Own Questions**: Write the SQL manually first
2. **Use Benchmarks**: Download Spider dataset, use their gold SQL
3. **Expert Review**: Have SQL expert verify generated SQL
4. **Multiple Attempts**: Generate with GPT, verify, use as gold for Ollama
